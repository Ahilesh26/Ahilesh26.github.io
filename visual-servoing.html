Visual Servoing Simulation for Automated Part Handling

Machine tending sounds mundane until you realise how much of precision manufacturing depends on it. The moment a CNC machine finishes a cycle, something has to pick up the finished part, inspect it, load a new blank, and close the door — consistently, accurately, thousands of times a shift. I set out to simulate a complete robotic CNC tending system not because a real robot was available, but because simulation is how you validate ideas before spending money on hardware. Build it in software first. Break it in software first. Understand exactly where it fails — then build the real thing.

The core challenge was visual servoing: using live camera feedback to continuously correct the robot's position rather than relying on a pre-programmed open-loop trajectory. In a real factory, parts arrive with tolerances. Pallets shift. Fixtures wear. Visual servoing turns those imprecisions from failures into corrections.

System Design

An adaptive gripper was designed capable of handling cylindrical billets, prismatic blanks, and finished parts without a tool change — parallel jaw geometry with compliant fingertips, sized to the part family while maintaining repeatability for tight-tolerance loading.

Image-based visual servoing (IBVS) was chosen over position-based approaches. Rather than reconstructing the 3D position of the part and computing a trajectory, IBVS minimises the error directly in the image plane. The robot moves until the observed feature positions match a set of target features — sidestepping coordinate frame calibration errors entirely.

Sensory Architecture

A wrist-mounted camera provides an eye-in-hand configuration — always relative to the grasp target. Feature extraction uses Harris corner detection and blob centroid tracking. The Jacobian relating image-space velocities to camera-frame velocities is computed analytically for each set of features, allowing the controller to invert it and drive the robot in Cartesian space at each timestep. Singular configurations are handled with a damped pseudo-inverse.

Task Sequencing

The full tending cycle is orchestrated by a finite state machine: approach → detect → align → grasp → retract → inspect → load → confirm → ready. Each transition is conditioned on both visual confirmation and simulated force data. If visual alignment fails to converge within a timeout, the system flags the part and requests operator intervention — a deliberate choice to avoid silently proceeding with a misaligned workpiece.

The IBVS controller works beautifully when the initial pose error is small, but degenerates badly when the camera starts far from the target. The fix was a two-phase approach: coarse open-loop approach to get within the convergence basin, then hand off to IBVS for the final precise alignment.
